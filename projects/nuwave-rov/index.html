The software that runs an underwater robot.

NUWave is the remotely operated vehicle (ROV) built by Northeastern's Marine Robotics team for the MATE ROV competition. Its software is a ROS 2 stack split between a topside laptop and a computer on the vehicle. My part is perception and testing: a crab-detection node, and the tests that keep the sensor nodes honest.

The team

What the club builds

Northeastern Marine Robotics, part of NURobotics, builds marine robots and works on making marine robotics more accessible. Its ROV competes in the MATE ROV Competition, where vehicles solve real-world tasks such as installing floating solar panels and modeling coral in 3D; the team's page says it has placed as high as 8th in the world. The club also builds an electric boat for the ASNE PEP race. The software group meets on Sundays. Team page

The stack

Two computers, one robot

The code lives in the public nuwave-rov repository. A pilot drives from a topside laptop (joystick input, the operator interface and the controllers), and a Nano computer on the vehicle runs the thruster output and power monitoring. Both run ROS 2 nodes that exchange messages. Sensor, camera and detection nodes sit in their own packages.

My part

Crab detection and tests

The crab recognition node looks for European green crabs: it runs a YOLO model on frames from up to four cameras. When the operator presses the detect button, it runs the model once on the latest frame from each camera, draws boxes and a per-camera crab count, and saves the annotated images with a timestamp and camera ID.

I wrote the package's README, then the node's unit tests. The suite uses a stand-in for the YOLO model and synthetic JPEG frames, so it runs without a GPU or a camera. It checks parameter defaults, the camera-count limit of one to four, frame buffering (only the latest frame is kept, undecodable data is ignored), the busy flag that stops overlapping detections, output file naming and folder creation, that only green crabs are drawn, and the per-camera and total counts in the log.

Direction

Where I want to take it

The vehicle's cameras and inertial sensor already produce the two streams that visual–inertial fusion needs. Underwater, turbidity, refraction and changing light break assumptions that hold in air, so the interesting work is detection and pose estimates that know when to distrust themselves. That is the same question I study in my other projects, and it is a direction, not a result: I have no underwater fusion results yet.

  • The detection model and its weights belong to the team; I did not train them.
  • The IMU tests are in review and not yet merged, and the depth-sensor tests are still in progress, so neither is claimed as finished.
  • No competition or pool results are reported here.
